# 银伴医院智能陪诊导引机器人 MVP

面向创新创业比赛的一周原型：浏览器负责老年友好交互、医院问答和路线展示，ESP32 巡线小车负责实体导引。默认使用模拟机器人，因此没有硬件和 API Key 也能运行完整软件演示。

## 当前能力

- 心内科、药房、卫生间、检验科和挂号处问询。
- 按说话顺序识别多个目的地，并按真实道路组合路线。
- 所有已规划路线均可启动屏幕模拟，“伴”图标会按同楼层道路节点移动。
- 一楼与三楼使用分层地图，跨楼层时明确显示进入电梯、上行或下行和出电梯过程。
- 常见就医流程回答。
- 大按钮、文字输入、浏览器中文语音输入和语音播报。
- 心内科、卫生间和药房三条实体黑线导引路线。
- 到达目的地后按当前已确认位置一键返回门诊大厅固定起点。
- 心内科跨楼层路线动画，以及“心内科后去卫生间”的三楼往返一楼动画。
- 模拟机器人完整状态流程。
- USB 或经典蓝牙虚拟串口控制 ESP32。
- STOP、障碍、丢线、路口转向超时、蓝牙断开和运行超时保护协议。

实体小车当前只负责同一楼层的受控巡线路段。它从门诊大厅左侧固定起点出发，可前往卫生间、药房或一楼 3 号电梯入口，并可沿配置路线返程。到达一楼 3 号电梯入口后，乘梯与三楼路线由屏幕模拟继续展示，不宣称实体小车能够自主乘梯。

## 快速启动

比赛电脑上最简单的方法是双击项目目录中的 `start-yinban.cmd`。该入口已固定使用真实硬件模式、蓝牙串口 COM6 和 115200 波特率，并且只为本次启动临时绕过 PowerShell 脚本限制，不会修改 Windows 的全局执行策略。如果设备管理器分配的发送端口发生变化，只需修改该文件顶部的 `YINBAN_ROBOT_PORT`。

也可以在 PowerShell 中进入本目录，然后运行：

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run.ps1

首次运行会创建 .venv 并安装依赖。看到服务启动后，在 Edge 或 Chrome 中打开：

    http://127.0.0.1:8000

启动脚本默认监听局域网地址，并会在窗口中显示供其他电脑访问的网址。另一台电脑必须与运行银伴服务的电脑处于同一局域网，然后打开类似下面的地址：

    http://100.71.120.221:8000

其中 IP 地址以启动窗口实际显示为准。不要在公共网络上转发或暴露 8000 端口。

也可以手动运行：

    python -m venv .venv
    .\.venv\Scripts\python.exe -m pip install -r requirements.txt
    .\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000

## 运行测试

    .\.venv\Scripts\python.exe -m pytest -q

## 连接真实小车

先在 Windows 中将 ESP32 经典蓝牙配对为虚拟 COM 口，或通过 USB 连接。然后在启动前设置：

    $env:YINBAN_MODE = "hardware"
    $env:YINBAN_ROBOT_PORT = "COM6"
    .\run.ps1

请把 COM6 替换为设备管理器中实际显示的发送端口。连接失败时，服务仍保持真实硬件模式，网页显示“正在重连”，并每两秒自动尝试恢复；不会把真实小车故障伪装成模拟模式。

真实小车上电或通信异常后默认处于“需要人工归位”。请把小车放回门诊大厅左侧起步线、让车头朝向 3 号电梯，再在网页点击“确认归位并复位”。通信恢复不会自动继续旧任务。

## 实体黑线地图

实体线路按网页一楼地图复刻，固定起点位于门诊大厅左侧：

```text
                     挂号处
                        │
固定起点 ── 门诊大厅 ── 3号电梯
               │        │
             卫生间    药房 ── 检验科
```

第一版只开放卫生间、3 号电梯和药房实体导引。挂号处、检验科仍可在网页查询和显示，但不会向小车发送实体路线。详细铺线和动作规则见 `docs/superpowers/specs/2026-09-17-physical-multi-route-return-design.md`。

## 项目边界

本项目是固定环境概念验证，不是可在真实医院通用部署的自主机器人。它不包含 SLAM、医疗诊断、真实挂号系统、患者身份识别或真实医护求助通知。

硬件接线、采购、演示和故障处理分别见 docs 目录。
