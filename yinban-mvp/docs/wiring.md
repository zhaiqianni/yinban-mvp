# ESP32 小车接线说明

以下引脚对应当前已经接线并完成阶段测试的 C-001 ESP32 小车。正式整合固件位于 `firmware/yinban_car/yinban_car.ino`，诊断程序保留在 `firmware/diagnostics` 下用于分模块复测。

## 默认引脚

| 模块 | 信号 | ESP32 GPIO |
|---|---|---:|
| 左电机 | 正向 / 反向 | 17 / 16 |
| 右电机 | 正向 / 反向 | 26 / 27 |
| 五路巡线 | OUT1–OUT5 | 13、18、19、34、35 |
| HS-SR04-L（专用插座 A0） | TRIG | 33 |
| HS-SR04-L（专用插座 A1） | ECHO | 32 |
| 自复位按钮 | SIGNAL | 25 |

GPIO 34、35 和 39 只能作为输入，适合巡线传感器，但不能用于电机或触发输出。

## 上电前检查

1. 关闭小车电源并断开电池。
2. 检查正负极、TB6612FNG 的 VM/VCC/GND 和电机输出。
3. ESP32、传感器和电机驱动必须共地。
4. 不要把普通 HC-SR04 的 5V Echo 直接接到 ESP32。
5. 用万用表确认巡线模块高电平不超过 ESP32 允许范围。
6. 抬起车轮，先空载测试左右轮方向。
7. 确认 STOP 后两侧电机都断驱动，再把车放到地面。

## 方向调整

如果后续更换电机导致某一侧前进方向反转，不要交换电池正负极。优先：

- 交换该电机接在 TB6612FNG 输出端的两根线；或
- 修改正式固件中对应的正向 / 反向 GPIO 映射。

## 巡线传感器

- 黑线宽度建议 18–25 mm。
- 传感器离地通常保持约 5–12 mm，按模块实际效果调整。
- 先低速测试直线，再测试半径较大的弯道。
- 如果黑白逻辑相反，修改 LINE_ACTIVE_LOW。

## 多路线场地

- 固定起点位于门诊大厅节点左侧，车头朝向 3 号电梯方向。
- 每个十字或丁字节点中心使用横向黑条，让至少四路传感器可同时识别。
- 小车在普通单线稳定后才会启用下一节点，防止同一横线被重复识别。
- 路线动作由网站发送：`S` 直行、`L` 左转、`R` 右转、`U` 原地掉头、`X` 到下一节点停车。
- 去程和返程动作保存在 `app/data/physical_routes.json`；固件还会再次核对六条允许的动作序列。
- 上电、蓝牙断开、途中停车、丢线或转向超时后，必须人工归位并在网页确认复位。

## 供电

优先采用套件卖家给出的配套供电方案。不要把电机直接接 ESP32 的 3.3V 或 5V 引脚。发现芯片过热、异味、线材发软或电池鼓包时立即断电。

## USB 与通信安全

- 当前 CH340 USB 串口为 `COM5`，端口号变化时以 `arduino-cli board list` 的实际结果为准。
- USB 线必须支持数据传输，并留出足够余量，避免小车或线缆拉扯导致 COM 口瞬间消失。
- Python 硬件模式每 500 毫秒发送一次 `PING`。
- 小车处于运行状态时，ESP32 连续 1500 毫秒没有收到有效命令即本地停车并锁定为 `ERROR:COMMUNICATION_TIMEOUT`。
- 通信恢复后不会自动启动，必须先复位，再重新发送开始命令。
- 蓝牙客户端在运行中断开时，固件会立即进入 `ERROR:COMMUNICATION_LOST`；1500 毫秒看门狗作为第二层保护。
