# 故障排查

## 页面打不开

确认 PowerShell 中服务没有退出，然后打开：

    http://127.0.0.1:8000/api/health

如果健康检查失败，重新运行：

    .\run.ps1

## 另一台电脑打不开页面

- 确认两台电脑连接同一个局域网或手机热点。
- 不要在另一台电脑上输入 `127.0.0.1`；应输入启动窗口显示的局域网地址，例如 `http://100.71.120.221:8000`。
- 确认服务监听 `0.0.0.0:8000`。
- Windows 防火墙如有提示，只允许 Python 在专用网络通信。
- 校园网、酒店网络可能启用设备隔离；这种情况下改用手机热点。
- 不要将 8000 端口映射到互联网。

## 中文语音按钮不可用

- 使用最新版 Edge 或 Chrome。
- 语音权限需要在用户点击按钮后授予。
- 现场噪声大时直接使用大按钮或文字输入。
- 语音识别不是 P0 的唯一入口，不要在现场反复调浏览器权限。

## 页面显示模拟模式

- 请从 `start-yinban.cmd` 启动比赛用服务；直接运行 `run.ps1` 且没有设置环境变量时默认用于软件模拟。
- 确认 `start-yinban.cmd` 中的 `YINBAN_ROBOT_PORT` 与设备管理器里的蓝牙发送端口一致。

## 页面显示正在重连

- 这表示网页后端正常，但真实机器人串口暂时不可用。
- 确认小车电池已开启、ESP32 指示灯正常，且 Windows 仍能看到对应蓝牙 COM 口。
- 关闭 Arduino 串口监视器等会占用 COM 口的软件。
- 无需重启网页或后端；COM 口恢复后，服务会每两秒自动重试并恢复连接。
- 如果设备管理器改变了端口号，关闭服务，修改 `start-yinban.cmd` 中的 COM6 后重新启动。

## 蓝牙无法形成 COM 口

- 确认主控是 ESP32-WROOM-32。
- 确认固件已经成功运行 SerialBT.begin。
- 删除旧配对后重新配对。
- 比赛前固定使用已经验证的电脑，不临时更换。
- 无法恢复时使用 USB 或模拟模式。

## 小车方向相反

抬起车轮后测试。交换对应电机的两根输出线，或修改固件的电机反转常量。

## 小车左右摆动

- 降低 BASE_SPEED。
- 降低 KP。
- 增加少量 KD。
- 调整传感器离地高度。
- 清理胶带反光、接缝和急弯。

## 小车经常丢线

- 增加黑线宽度。
- 放大弯道半径。
- 重新调整五路传感器电位器。
- 检查杜邦线是否松动。
- 先只保留直线加缓弯的一条路线。

## 超声波错误停车

- 确保传感器正对前方且没有被车壳遮挡。
- 检查供电和共地。
- 将障碍阈值从 20 cm 小幅降低。
- 保留连续多次读数确认，不要用一次测距直接停车。

## ESP32 反复重启

- 立即断电并检查短路。
- 电机不能由 ESP32 供电引脚直接驱动。
- 检查电池电压、TB6612FNG 供电和共地。
- 固定松动线材，避免电机启动时接触不良。
