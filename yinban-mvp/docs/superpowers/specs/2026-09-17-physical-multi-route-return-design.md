# 银伴实体多路线与一键返程设计

## 1. 背景

当前银伴实体小车只能接受 `START:CARDIOLOGY`，沿单条黑线行驶并在终点停车。它尚不能在十字或丁字路口根据目的地选择方向，也不能在到达后自动返回门诊大厅。网页一楼地图已经包含门诊大厅、卫生间、3号电梯、挂号处、药房和检验科，因此下一阶段要让实体黑线地图与网页地图采用相同拓扑，并为三个目的地提供可重复的去程和返程演示。

本设计面向固定场地比赛原型，不包含陌生地图识别、SLAM、任意位置启动或自主乘坐电梯。

## 2. 目标和范围

第一版实体导引开放三个目的地：

- 卫生间；
- 3号电梯口；
- 药房。

用户选择心内科时，实体小车只行驶到一楼3号电梯口；随后由网页继续展示乘梯和三楼路线。

第一版还提供从上述三个目的地一键返回固定起点的能力。挂号处和检验科保留在网页与实体线路上，但暂不开放实体导引按钮。

## 3. 方案比较

### 3.1 路口动作队列

网站根据目的地生成由直行、左转、右转、掉头和停车组成的动作队列，ESP32在检测到节点时依次执行。它能复用同一套状态机，增加路线时主要修改配置，适合当前硬件和比赛周期。本设计采用此方案。

### 3.2 每个目的地独立状态机

分别编写卫生间、电梯和药房的专用函数，短期直观，但去程、返程和异常处理会重复，路线增加后难以维护。不采用。

### 3.3 节点定位标签

在节点增加RFID、二维码或磁性标记可以提高定位可靠性，但需要额外硬件和调试，不符合当前预算与进度。不采用。

## 4. 实体地图

实体黑线按照网页一楼地图复刻：

```text
                     挂号处
                        │
固定起点 ── 门诊大厅 ── 3号电梯
               │        │
             卫生间    药房 ── 检验科
```

铺设规则：

- 固定起点位于门诊大厅左侧，小车每次去程都朝向3号电梯放置；
- 使用已经通过循迹测试的18至25毫米黑胶带；
- 相邻节点尽量保留至少50厘米直线；
- 转弯使用圆弧，建议半径不小于30至35厘米；
- 每个路口中心增加覆盖五路传感器宽度的横向识别条；
- 固定起点和卫生间末端使用双横线节点标记；
- 挂号处与检验科支线可以铺设，但第一版不会向它们发送实体路线。

实际尺寸以五路传感器正常离地高度下的现场测试为准。尺寸调整不能改变节点连接关系，否则网页地图与实体路线会再次失配。

## 5. 路口识别与动作执行

### 5.1 节点识别

五路传感器中至少四路同时检测到黑色并持续约30毫秒时，确认进入节点。完成一次动作后进入防重复触发阶段，必须先离开全黑区域并重新稳定捕获普通单线，才能识别下一个节点。

双横线会形成两个相邻的全黑脉冲，固件用它识别固定起点或末端节点。开始运行或完成掉头后，固件会忽略刚刚离开的节点一次，避免立即重复触发。

### 5.2 动作定义

- `S`：在下一个节点直行；
- `L`：在下一个节点左转；
- `R`：在下一个节点右转；
- `U`：启动路线时原地掉头；
- `X`：在下一个节点停车并上报到达。

直行时，小车越过横向识别条并重新捕获中线。左转或右转时，小车先短距离进入节点中心，再原地旋转；经过最短防误判时间后，以中间传感器连续稳定捕获目标线作为转向完成条件。转向超过约1.5秒仍未找到目标线时立即停车并报告路口超时。

掉头只允许作为返程动作队列的第一项。固件原地旋转，越过原方向后重新捕获返程黑线；超过约2.2秒未完成时停车并报告掉头超时。

## 6. 路线配置

第一版路线定义如下：

| 实体任务 | 去程动作 | 返程动作 |
|---|---|---|
| 卫生间 `TOILET` | `R,X` | `U,L,X` |
| 3号电梯/心内科实体段 `CARDIOLOGY` | `S,X` | `U,S,X` |
| 药房 `PHARMACY` | `S,R,X` | `U,L,S,X` |

动作在节点事件发生时依次消费。`U`在返程启动时立即执行，不等待下一个节点；其余动作均由后续节点触发。

后端新增独立实体路线配置，使页面可用性、发送给ESP32的动作和测试预期来自同一数据源。固件只负责验证并执行收到的有限动作集合，不根据自然语言自行推断路线。

## 7. 通信协议

Python后端继续独占Windows蓝牙串口，浏览器不直接访问蓝牙。新增运行命令：

```text
RUN:CARDIOLOGY:S,X
RUN:TOILET:R,X
RUN:PHARMACY:S,R,X
RUN:RETURN_TOILET:U,L,X
RUN:RETURN_CARDIOLOGY:U,S,X
RUN:RETURN_PHARMACY:U,L,S,X
```

允许的任务编号、动作字符和最大动作数量由后端与固件共同校验。非法任务、非法动作、空队列或过长队列必须拒绝，不能进入电机状态。

ESP32新增事件：

```text
MOVING:PHARMACY
NODE:PHARMACY:1
TURNING:RIGHT
ARRIVED:PHARMACY
ERROR:JUNCTION_TIMEOUT
```

现有 `PING`、`STOP`、`RESUME`、`RESET` 继续保留。`RESUME`只用于障碍解除后继续尚未完成的队列；丢线、转向超时、人工停止或位置未知时不能直接继续。

## 8. 后端设计

后端新增实体路线目录，负责：

- 判断目的地是否支持实体导引；
- 生成去程或返程动作队列；
- 将动作队列编码为受限蓝牙命令；
- 在状态快照中记录当前任务、方向、已完成节点序号和当前位置；
- 拒绝与当前位置不一致的开始或返程请求。

新增返程接口。请求必须指明当前已到达的实体任务，后端同时核对ESP32最近一次到达状态；只有两者一致时才发送返程队列。

状态模型新增以下信息：

- 当前任务编号；
- 运行方向：去程或返程；
- 已完成节点序号；
- 已确认的实体位置；
- 是否需要人工放回起点并复位。

蓝牙断线自动恢复机制继续使用现有实现。重连只恢复通信，不自动恢复电机任务。

“已在固定起点”由人工归位确认建立：用户将小车放回门诊大厅左侧起步线、确认车头朝向3号电梯，然后在网页点击“确认归位并复位”。后端与固件清除旧任务并把实体位置设为固定起点。现有传感器不能在静止状态下独立证明车身位置和朝向，因此网页必须明确提示这一人工确认前提，不能把普通 `RESET` 描述成自动定位。

## 9. 网页设计

- 心内科、卫生间和药房均显示实体导引可用；
- 心内科仍在3号电梯口完成实体交接，再由屏幕继续三楼动画；
- 机器人状态区域显示当前实体位置和节点进度；
- 到达三个实体目的地之一后显示“返回门诊大厅”按钮；
- 返程时地图上的“伴”图标沿相反方向移动；
- 到达固定起点后恢复“等待任务”；
- 页面刷新后根据后端快照恢复任务显示，不只依赖浏览器内存；
- 位置未知时禁用开始与返程，显示“请将小车放回固定起点并复位”。
- “确认归位并复位”按钮必须先显示放置位置和朝向说明，再由用户确认；确认后才允许新的去程。

网页地图节点和实体路线目录使用同一组节点标识，以防路线文案、动画和实物再次不一致。

## 10. 状态与安全约束

- 新去程只能从已确认的固定起点开始；
- 返程只能从已确认到达的卫生间、电梯口或药房开始；
- 小车到达后若被人工挪动，必须放回固定起点并复位；
- 蓝牙断线或小车断电后，后端不得自动续跑上一次任务；
- 超声波检测到障碍时制动，障碍解除后允许人工继续当前队列；
- 丢线、传感器异常、路口超时、掉头超时、路线总超时和通信看门狗触发时立即制动；
- 人工停止发生在路线中途时，位置被标记为未知，不能直接返程；
- 本地停车按钮始终具有最高优先级。

## 11. 测试与验收

### 11.1 自动化测试

- 三条去程和三条返程动作序列完全匹配配置；
- 未开放的挂号处与检验科不能启动实体导引；
- 协议拒绝非法任务、非法动作、空队列和过长队列；
- 节点事件能更新动作索引和位置快照；
- 页面刷新后能从状态接口恢复当前任务；
- 位置未知、断线和非到达状态不能启动返程；
- 障碍暂停只在合法状态下允许继续；
- 现有蓝牙自动重连测试继续全部通过。

### 11.2 分阶段实机测试

1. 抬起驱动轮，分别测试 `S`、`L`、`R`、`U` 和 `X`；
2. 使用单个路口测试进入节点、完成动作和防重复触发；
3. 铺设与网页拓扑一致的完整黑线地图；
4. 分别执行卫生间、电梯口和药房去程；
5. 分别执行三条自动返程；
6. 在不同路段加入障碍并测试停车与继续；
7. 测试丢线、人工停止和蓝牙断线后的安全复位；
8. 每条去程与返程连续成功三次后才计为通过。

## 12. 验收结论标准

满足以下条件后，实体多路线功能才算完成：

- 网页地图、实体黑线和动作配置拓扑一致；
- 三个目的地均能从固定起点正确到达；
- 三个目的地均能一键返回固定起点；
- 到达、返程、障碍和错误状态能在网页正确显示；
- 任意错误都不会导致小车在位置未知时继续运行；
- 六条路线各连续成功三次。
