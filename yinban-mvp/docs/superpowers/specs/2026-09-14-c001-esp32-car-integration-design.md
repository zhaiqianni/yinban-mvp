# 银伴 C-001 ESP32 小车接入设计

日期：2026-09-14  
状态：已由用户确认设计方向，待按本文实施与实车校准

## 1. 目标

将已经组装完成的 C-001 综合智能小车接入银伴网页端，使比赛现场能够演示“用户选择目的地—网页显示路线—小车沿黑线前往电梯口—遇障停车—到达终点”的完整闭环。

第一版只承担单楼层内的实物移动：门诊大厅至 3 号电梯口。乘梯及三楼电梯口至心内科的过程继续由网页动画模拟，不宣称小车具备真实医院的自主跨楼层导航能力。

## 2. 已确认硬件

- 小车主控为已安装在车体上的 `ESP32-WROOM-32EA-MOC` 一体化控制板。
- 额外的 `ESP32-EXA3` 是另一种扩展方案，不与当前一体化主控板叠插。
- USB 转串口芯片为 CH340，Windows 已正确识别为 `COM5`。
- 程序烧录和传感器读数检查可仅使用 USB 供电；电机运动测试才安装 14500 电池。
- 采用五路下视循迹模块、左右电机和超声波模块。前方红外避障模块暂不接入第一版。

## 3. 开发方式选择

采用 Arduino C++，不以 Mixly 或 MicroPython 作为最终运行环境。

理由：Arduino C++ 可使用 ESP32 的经典蓝牙串口，能与现有 Python 网页后端的串口通信方式对接；代码可以进入 GitHub 版本管理，也便于后续增加状态机、超声波避障、终点判断和故障信息。

厂家 Mixly 示例只作为硬件引脚和基础动作的校验依据，不直接作为最终程序。

## 4. 引脚定义

以下定义以厂家 ESP32 接线说明及巡线示例为准：

| 功能 | GPIO | 行为 |
| --- | ---: | --- |
| 左电机正向 | 17 | PWM 输出 |
| 左电机反向 | 16 | PWM 输出 |
| 右电机反向 | 27 | PWM 输出 |
| 右电机正向 | 26 | PWM 输出 |
| 五路循迹 OUT1～OUT5 | 13、18、19、34、35 | 数字输入 |
| 本地停车按钮 | 25 | 数字输入 |
| 超声波 Trig（扩展板 A0） | 33 | 数字输出 |
| 超声波 Echo（扩展板 A1） | 32 | 数字输入 |

厂家巡线示例的传感器逻辑为：`0` 表示非黑色地面，`1` 表示检测到黑线。实车调试时必须打印原始读数复核；若模块电平与示例相反，只修改统一的极性配置，不在多处分散反转逻辑。

## 5. 固件结构

固件采用非阻塞状态机，至少包含以下状态：

- `IDLE`：上电安全停止，等待命令。
- `MOVING`：沿黑线运行。
- `BLOCKED`：前方连续三次低于 25 厘米后停车；移开障碍物也保持停车，确认安全且收到 `RESUME` 后才恢复。
- `ARRIVED`：确认横向终点线后停车并上报到达。
- `ERROR`：丢线、传感器异常或未知路线时停车。

只读校准由独立诊断固件完成，不作为正式运行状态。收到 `STOP` 后进入 `IDLE` 并保持电机关闭；`RESUME` 仅用于解除已经确认安全的 `BLOCKED` 状态。

无论处于何种状态，无法解析命令、串口断开或检测到安全故障时均不得继续盲目前进。

## 6. 五路传感器巡线规则

第一版根据 OUT1～OUT5 的位置加权计算偏差。中间探头检测到黑线时直行；黑线逐渐移向左侧探头时向左修正，移向右侧探头时向右修正。五路全部丢线时立即停车；五路连续同时检测到终点宽黑条并达到确认时长后，进入到达状态。具体极性、速度和确认时间通过实车低速测试校准。

## 7. 实体路线设置

第一版路线采用可移除的哑光黑色胶带铺设在浅色、无强反光的平整地面上：

1. 起点代表门诊大厅。
2. 单条连续黑线代表前往 3 号电梯口的走廊。
3. 弯道采用大圆弧，避免直角转弯；初始转弯半径不小于车身长度的两倍。
4. 终点使用横跨两只循迹传感器的宽黑条，代表 3 号电梯口。
5. 第一版不设置岔路选择；目的地不同但共用电梯口时，共用同一条实物路线，后续楼层路径由网页区分。

网页中的地图是演示用逻辑地图，实体小车的路径由胶带几何形状决定，两者需使用相同的起点、终点名称和阶段状态，但不假装进行真实地图坐标定位。

## 8. 蓝牙与网页通信

ESP32 使用内置经典蓝牙 SPP，广播名称设为 `YINBAN_ROBOT`。Windows 配对后产生虚拟串口，网页后端继续通过现有 `pyserial` 链路发送文本命令。

保留现有命令：

- `PING`
- `START:CARDIOLOGY`
- `STOP`
- `RESUME`
- `RESET`

保留现有状态消息：

- `READY`
- `MOVING`
- `BLOCKED:<厘米>`
- `LINE_LOST`
- `ARRIVED:CARDIOLOGY`
- `ERROR:<原因>`

USB 串口和蓝牙串口使用同一套解析器与状态输出，便于先通过 `COM5` 调试，再切换到蓝牙虚拟 COM 端口。

### 8.1 通信看门狗

真实硬件模式下，Python 后端每 500 毫秒向 ESP32 发送一次 `PING`。ESP32 在执行 `START:CARDIOLOGY` 或 `RESUME` 后启动通信计时；收到任意格式正确的白名单命令时刷新计时。小车处于 `MOVING` 状态且连续 1500 毫秒没有收到有效命令时，必须在本地关闭两侧电机、进入锁定错误状态，并上报：

```text
ERROR:COMMUNICATION_TIMEOUT
```

通信恢复、串口重新打开或障碍物移除均不得让小车自行重新运动。发生通信超时后，必须由电脑重新连接，并重新发送 `RESET` 和 `START:CARDIOLOGY` 才能开始下一次任务。

Python 后端若捕获串口读写异常，立即将硬件状态标记为断开，并把具体错误显示在网页端。此时不把“已尝试发送 STOP”误报为“已经停车”；实体停车由 ESP32 通信看门狗独立保证。`PING` 在空闲状态返回 `READY`，在运行或异常状态返回当前真实状态，避免网页把正在运动的小车误判为空闲。

## 9. 分阶段实施

### 阶段一：烧录与传感器检查

安装 Arduino 构建工具和 ESP32 开发板支持，使用 `COM5` 烧录只读诊断程序。诊断程序每隔固定时间输出左右循迹读数和超声波距离，不驱动电机。

### 阶段二：电机方向检查

安装电池后把小车架空，分别以低 PWM 短时间驱动左、右电机，确认正转、反转和停车。若方向相反，只修改电机方向配置。

### 阶段三：基础巡线

在短直线和大圆弧上低速测试，调节传感器高度、模块电位器、基础速度和转向差速，确认不会频繁冲出黑线。

### 阶段四：终点与避障

加入宽黑条终点确认和超声波停车，验证临时遮挡不会触发到达，障碍物移除后能够按设计恢复。

### 阶段五：网页联调

先用 USB `COM5` 验证网页命令，再配对 `YINBAN_ROBOT` 蓝牙并改用 Windows 蓝牙虚拟串口。网页的按钮、路线动画和小车状态必须保持一致。

## 10. 安全约束

- 烧录和静态检测时不安装电池。
- 首次电机测试必须架空车轮，并准备随时断电。
- 插拔主控、传感器或电机线前必须断开 USB 和电池。
- 不允许仅靠固定时间盲跑整段路线。
- 丢线、双传感器异常或障碍距离无效时默认停车。
- 14500 电池必须同型号、同容量、同电量并按电池盒极性安装，禁止混用或反装。

## 11. 验收标准

完成版本应满足：

1. 上电及复位后车轮不自行转动。
2. USB 和蓝牙均能执行 `PING`、开始、暂停、继续和复位命令。
3. 小车能在比赛布置的直线与圆弧黑线上连续行驶至电梯口终点。
4. 宽黑条被稳定识别为终点，并只上报一次 `ARRIVED:CARDIOLOGY`。
5. 前方出现障碍时能够停车并向网页上报阻挡状态。
6. 网页所显示的当前阶段与实体小车状态一致。
7. 连续完成至少 10 次完整演示，其中不少于 9 次无需人工扶正或重启。
8. 小车运行中关闭或中断 Python 后端后，应在 1500 毫秒通信超时阈值附近自行停车，且恢复连接后不得自动重启。
