# 银伴蓝牙断线自动恢复实施计划

## 目标

按照已确认的设计，使真实硬件串口断开时不再拖死网页后端，并在 Windows 重新提供指定 COM 口后自动恢复连接。

## 实施步骤

1. **先补自动化测试**
   - 扩充 `tests/test_serial_robot_link.py`。
   - 覆盖首次打开失败、重复重试后恢复、读写失败、阻塞写入不阻塞状态、离线命令失败、关闭释放资源。
   - 增加硬件模式不静默回退模拟模式的断言。

2. **重构串口连接层**
   - 修改 `app/services/robot_link.py`。
   - 分离状态锁、写锁和连接锁。
   - 添加读写超时、后台重连线程和安全关闭逻辑。
   - 保证 `status()` 不执行串口 I/O，且断线状态立即返回。

3. **修正硬件模式语义**
   - 硬件模式始终使用可恢复串口控制器。
   - 首次连接失败只显示离线并持续重连，不切换为模拟机器人。

4. **改造网页状态轮询**
   - 修改 `app/web/js/app.js`。
   - 所有 API 请求增加三秒超时。
   - 用单次递归定时器替代重叠的固定间隔轮询。
   - 区分“机器人正在重连”和“后端连接失败”。
   - 机器人离线时禁用实体开始和继续按钮。

5. **验证与交付**
   - 运行完整 Python 测试和 JavaScript 语法检查。
   - 以真实硬件模式启动服务，验证 COM 口不可用时状态接口仍快速响应。
   - 开展三轮实机断电、上电、自动重连和命令恢复测试；全部通过后才确认永久恢复完成。
