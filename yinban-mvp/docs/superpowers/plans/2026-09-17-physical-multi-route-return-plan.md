# 银伴实体多路线与一键返程实施计划

## 目标

在保持现有蓝牙自动恢复、循迹、超声波和安全停车能力的前提下，使银伴能够从固定起点前往卫生间、3号电梯口或药房，并从三个目的地一键返回门诊大厅固定起点。

## 阶段一：路线目录与协议

1. 新增 `app/data/physical_routes.json`，保存三条去程、三条返程、实体位置和网页节点。
2. 新增实体路线目录类，集中完成路线查询、动作校验和去返程任务编号生成。
3. 扩充 `RobotSnapshot` 与事件解析，支持归位状态、运行方向、节点序号和转向状态。
4. 新增受限 `RUN:<任务>:<动作队列>` 编码，拒绝未知任务、非法动作、非法掉头位置和不以停车结束的队列。
5. 先补测试，再实现上述能力。

## 阶段二：机器人控制器与API

1. 将实体路线目录注入模拟控制器和串口控制器。
2. 扩展控制器接口，加入 `return_to_start()`。
3. 硬件连接或重连后默认要求人工归位，不自动假定位置正确。
4. 只有 `HOME_READY` 状态允许新去程；只有匹配的到达状态允许返程。
5. 扩展状态响应，返回方向、节点序号、位置、归位要求和可返程任务。
6. 新增 `/api/robot/return`，并把 `/reset` 明确为“确认归位并复位”。
7. 扩充API、模拟控制器和串口控制器测试。

## 阶段三：导航数据与网页

1. 为卫生间和药房启用实体路线编号，挂号处与检验科保持仅屏幕展示。
2. 更新快捷入口、路线说明和实体状态文案。
3. 新增“返回门诊大厅”按钮和人工归位确认交互。
4. 根据后端状态恢复当前位置、去返程方向和地图动画。
5. 位置未知、断线或状态不允许时禁用开始和返程。
6. 使用真实浏览器验证选择路线、到达、返程、刷新恢复和错误提示。

## 阶段四：ESP32固件

1. 用动作队列替换单一 `START:CARDIOLOGY` 路线。
2. 实现节点确认、防重复触发、直行穿越、左右转和原地掉头状态机。
3. 支持 `RUN`、`HOME_READY`、`NEEDS_RESET`、`NODE` 和 `TURNING` 协议。
4. 保留超声波锁定停车、人工继续、通信看门狗、本地停车按钮、丢线停车和总超时。
5. 任何中途人工停止、丢线、转向失败或通信故障都进入需要人工归位状态。
6. 编译固件；编译工具不可用时至少进行静态检查，并在烧录前明确说明。

## 阶段五：集成验证

1. 运行完整Python测试与JavaScript语法检查。
2. 在模拟模式验证三条去程和三条返程API与网页流程。
3. 在不驱动电机的条件下验证真实蓝牙命令与状态。
4. 烧录前由用户确认小车架空和场地安全。
5. 按单动作、单路口、完整去程、完整返程的顺序进行实机测试。
